# Agent Note: skill 的改动在发布时安装，而不是在编辑时

Status: implemented

[English](2026-09-16-install-at-release-time.md) | 中文

## 问题

在本仓库编辑的 skill 与 agent 环境实际运行的副本是两件产物，而仓库没有写明两者之间的同步点。贡献者——或帮助贡献者的 agent——会把工作区里的改动读成「已安装的 skill 已经带上它」，于是把编辑过的目录复制进已安装的 skills 目录。那份副本没有版本管理、会与仓库漂移，也掩盖了这次改动究竟有没有走过 pack 自己的安装路径。重命名或移动 skill 时这种诱惑最强，因为已安装目录里那时还留着一个源码已经不用的名字。

## 决策

在根 `AGENTS.md` 的安装一节写明边界：在这里编辑 skill 只改变源码，已安装副本在 pack 被安装或发布时更新，因此开发中的 skill 在那次安装之前保持未安装状态。仓库的安装脚本仍是已安装目录的唯一写入者。

## 备选方案

- **在重命名或移动 skill 的改动里顺手同步已安装副本。** 否决：它让某一个环境更好读，却制造出第二个没有任何 gate 检查的真理来源——已安装目录是构建产物，它一旦偏离，本仓库的每一项检查都看不见。
- **不写明边界，依赖安装脚本文档本身。** 否决：安装脚本讲的是怎么装，而不是什么时候该装；而这个问题出现在撰写阶段，不在安装时刻。

## 后果

- skill 的名称、路径或内容的改动只落在仓库里；agent 环境在新版本被安装之前一直运行上一个发布状态。
- 评审者在 diff 里读到开发中的 skill，而不是在某个已安装目录里。
- 发布与安装仍是源码通往可用 skill 的唯一路径，因此环境里运行的东西始终是 pack 的一个已发布状态。
